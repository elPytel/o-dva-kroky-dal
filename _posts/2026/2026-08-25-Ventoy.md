# Konec neustálého formátování flashek. Proč nedám dopustit na Ventoy

Znáte to. Potřebujete přeinstalovat Windows, vezmete flashku a naformátujete ji. Za týden potřebujete nabootovat live Linux nebo zachraňovat data, tak ji naformátujete znovu. Takhle jsem to dělal roky a stálo mě to zbytečně moc času. Pak jsem ale objevil Ventoy a už nikdy se k původnímu postupu nevrátím (pokud nebudu muset instalovat Proxmox).

## Co je vlastně Ventoy?

Ve zkratce je to open-source nástroj pro tvorbu bootovacích USB disků. Hlavní rozdíl oproti klasickým nástrojům je ale v tom, že disk formátujete jen jednou při prvotní instalaci Ventoy!

Zbytek disku se pak chová jako běžné datové úložiště. Bootovatelné ISO soubory (případně i WIM, IMG, VHD nebo EFI) na něj prostě jen překopírujete ve správci souborů. Můžete je i libovolně třídit do složek. Když pak z flashky nabootujete, Ventoy to všechno dynamicky načte a nabídne vám přehledné menu, ze kterého si vyberete, co chcete spustit. Podporuje x86 Legacy BIOS i UEFI (včetně Secure Boot) a spolkne skoro cokoliv od Windows a Linuxu přes různé záchranné utility až po hypervizory.

## Moje 32GB Sony flashka

Osobně mám Ventoy hozený na jedné 32GB flashce. Slouží mi jako jedna fleška, která vládne všem, vejde se na ní obrovská hromada obrazů. Aktuálně na ní nosím vedle sebe:

* Instalačky Windows,
* Různé distribuce Linuxu,
* Windows Recovery nástroje,
* GParted.

Nemusím řešit, jestli mám po ruce správnou flashku, prostě sáhnu po jedné a nabootuju přesně to, co zrovna situace vyžaduje.

```
Hiren_Boot_PE_[win_repair_kit].iso  
gparted-live-1.3.1-1-amd64.iso
Norton Bootable Recovery Tool.iso    
netboot.xyz.iso
Zorin-OS-16.3-Core-64-bit.iso          
proxmox-ve_9.2-1.iso
chntpw.iso                             
ubuntu-26.04-desktop-amd64.iso
dsl-4.4.10.iso
```

## Customizace GRUBu je top

Co mě ale na celém nástroji baví nejvíc, je možnost úprav. Pod kapotou bootovacího menu běží GRUB a Ventoy nabízí skvělé možnosti, jak si to celé přizpůsobit obrazu svému.

Témata a konfigurace se nastavují přes konfigurační soubor `ventoy.json` umístěný přímo ve složce `ventoy` na prvním (datovém) oddílu flashky.

Struktura na flashce by měla vypadat takto:

```text
/ventoy/
├── ventoy.json
└── themes/
    ├── moje_tema_1/
    │   └── theme.txt
    └── moje_tema_2/
        └── theme.txt
```

### Konfigurace v `ventoy/ventoy.json`

Otevřete či vytvořte soubor `ventoy/ventoy.json` a zadejte cesty k `theme.txt`. Cesty se uvádějí relativně ke kořeni datového oddílu:

```json
{
    "theme": {
        "file": "/ventoy/themes/moje_tema_1/theme.txt",
        "gfxmode": "1920x1080"
    }
}
```

Pro správnou konfiguraci motivů ve Ventoy je potřeba mít správnou adresářovou strukturu a konfigurační soubor `ventoy.json` umístěný v kořenovém adresáři prvního oddílu flashdisku ve složce `ventoy`.

### Doporučená struktura adresářů

```text
/ventoy/
├── ventoy.json
└── themes/
    ├── muj_theme_1/
    │   ├── theme.txt
    │   ├── background.png
    │   └── ...
    └── muj_theme_2/
        ├── theme.txt
        └── ...
```

### Rotace více témat náhodně

Pokud chcete střídat více motivů náhodně při každém bootu, zadejte pole cest:

```json
{
    "theme": {
        "file": [
            "/ventoy/themes/muj_theme_1/theme.txt",
            "/ventoy/themes/muj_theme_2/theme.txt"
        ],
        "gfxmode": "1920x1080",
        "display_mode": "GUI"
    }
}
```

* Cesty v `ventoy.json` jsou vždy **case-sensitive** a relativní k rootu datového oddílu.
* Každé GRUB téma musí mít svůj vlastní soubor `theme.txt`.

## Aktualizace Ventoy (Linux)

Stáhněte se i aktuální verzi Ventoy a rozbalte taxball. V terminálu se přesuňte do rozbaleného adresáře a spusťte příkaz:

```bash
lsblk
sdb           8:16   1  29,3G  0 disk 
├─sdb1        8:17   1  29,3G  0 part /run/media/pytel/Ventoy
└─sdb2        8:18   1    32M  0 part 
```

Zde nahradtě /dev/sdb za zařízení, na kterém máte Ventoy. V mém případě je to /dev/sdb. Příkaz -u znamená update, takže se zachovají všechny soubory na disku.

```bash
sudo umount /dev/sdb*
sudo ./Ventoy2Disk.sh -u /dev/sdb
```
