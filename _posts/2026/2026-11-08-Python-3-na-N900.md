Nokia N900 má Python od výroby, jenže je to **Python 2.5**. Na něm běží aplikace Hildonu, třeba můj `mutt-hildon`, a jeho nahrazení by je rozbilo. Pro nové programy (například yt-dlp nebo gPodder 3) ale potřebuju moderní Python. Proto jsem pro N900 přeložil **Python 3.11** a dal ho vedle toho starého. Vychází z mého dřívějšího pokusu Python_3.11_on_N900, jehož chyby jsem opravil.

## Proč Python 3

- Moderní nástroje a knihovny jsou už jen pro Python 3.
- Starý Python 2.5 zůstává nedotčený. `python` je pořád 2.5, nový se jmenuje `python3` (odkaz v `/usr/bin`, celý strom je v `/opt/python3`).
- Je to základ pro další programy, třeba pro stahování z YouTube nebo pro podcasty.

## Jak jsem ho přeložil

Překládá se cross-kompilací ve Workshopu, stejně jako ostatní programy (viz [článek o sestavování]({{ site.baseurl }}{% post_url 2026/2026-11-03-Jak-sestavovat-programy-pro-N900 %})). Zajímavé volby ve `build.sh`:

- Wrapper `maemo-gcc` a sysroot z SDK, abych dostal `GLIBC_2.4` a ne novější.
- Nativní „build python“ stejné verze (`--with-build-python`), bez PGO.
- `ac_cv_buggy_getaddrinfo=no`, aby zůstalo IPv6, a `ac_cv_file__dev_ptmx=yes`.
- Pkg-config vypnutý, parametry pro `curses` a `sqlite3` zadávám ručně.
- Bajtkód se předkompiluje při sestavení: první spuštění na procesoru 600 MHz by jinak trvalo dlouho a `/opt` nemusí být zapisovatelný.

Knihovny, které telefon nemá nebo má příliš staré, se přilinkují staticky: OpenSSL 3.5, SQLite 3.50 (systémový 3.6 je pro Python 3.11 příliš starý) a ncursesw. Staví je `deps.sh` a linkování modulů zajišťuje `ldshared.sh`.

## Co obsahuje

- **`ssl` s OpenSSL 3.5** (statický), takže funguje **TLS 1.3**. Kořenové certifikáty se berou z balíčku `curl` (`sitecustomize.py` nastaví `SSL_CERT_FILE`).
- **`sqlite3`** s vlastním SQLite 3.50.
- `zlib`, `curses` a `curses.panel`, `socket`, `threading`, `subprocess`, `pty` a zbytek standardní knihovny.

Balíček `python3.11` má **19 MB** (rozbalený 55 MB). Instaluje se do `/opt`, který je na oddílu `/home`, takže malý kořenový systém s 57 MB volného místa se nezaplní.

## Jak to funguje na telefonu

Testy (`make -C apps/python3 test`, 20 kontrol) projdou na skutečném telefonu. Ukázkový program vypíše verzi Pythonu a SQLite, stáhne `https://api.github.com/zen` přes TLS 1.3 (0,7 s) a spočítá 300 000 čtverců (0,7 s). Celé spuštění i s importy trvá asi 3 sekundy. Na pomalém procesoru je to víc, než by člověk chtěl, ale pro skripty to stačí.

### pip

Později jsem doplnil `pip`. 

Postup:

```bash
python3 -m ensurepip
python3 -m pip install nejaky-balicek
```

Čistě pythonové balíčky půjdou, balíčky s kódem v C (vyžadují kompilátor) ne. Přibyly také `readline`, `ctypes` (libffi), `bz2` a `lzma`. Po přidání je balíček s `pip` velký 79 MB po rozbalení.

## Okna Hildon z Pythonu 3

Aplikace s grafickým rozhraním Hildon používají PyGTK, které je jen pro Python 2. Nativní vazby pro Python 3 neexistují: PyGObject potřebuje GObject Introspection, které pro GTK 2 a Hildon nikdo nevytvořil. Přesto to jde, **přes `ctypes`**. Python 3.11 otevře okno `HildonStackableWindow` a `HildonButton` a obsluhuje signály (zpětná volání jako `CFUNCTYPE`, časovače přes `g_timeout_add`). Cena je ruční psaní každého volání (typy argumentů, `restype = c_void_p` u konstruktorů). Rozumné řešení je malá vrstva s třídami Window, Button, Label, Box a dalšími. To je zatím jen nápad.

## Co chybí

`tkinter`, `uuid`, `dbm` a `gdbm`. Moduly se dají doplnit podle potřeby, kdyby je nějaký program chtěl.

Python 3.11 je v apt repozitáři `n900-resurrection.github.io/n900-repository` (balíček `python3.11`), zdroje v organizaci [n900-resurrection](https://github.com/n900-resurrection).
